# Governance

Protocol governance is the process by which people propose, implement, coordinate, accept, reject, or ignore changes. No proposal document, developer meeting, miner signal, validator vote, client release, or token ballot controls a permissionless network by itself. Effective change requires enough of the ecosystem to run and build on compatible rules.

This section separates publication, technical review, implementation, activation, and adoption. It also distinguishes base-layer governance from DAO governance, where contracts can count votes and execute specific actions on-chain.

## Three layers of a decision

A governance analysis should ask:

1. Who can propose and publish the idea?
2. Who can implement, release, activate, or execute it?
3. Who can refuse it and continue under another rule set?

Answers may differ. Editors can merge a specification without persuading implementations. Client teams can release code users decline to run. Miners or validators can order blocks but cannot make fully validating nodes accept blocks that violate their rules. Token voters can pass a proposal that a multisig still controls in practice.
