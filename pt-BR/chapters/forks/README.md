# Atualizações de forks e protocolos

"Forquilha" descreve vários eventos genuinamente diferentes compartilhando uma palavra sobrecarregada. Esta seção separa-os precisamente, uma discordância de rotina, auto-resolver-se sobre a ponta da corrente não é o mesmo tipo de evento como um soft fork, que não é o mesmo tipo de evento como um hard fork, que não é o mesmo tipo de evento que as divisões específicas, historicamente contenciosas abrangidas nos estudos de caso desta seção. Obter este vocabulário é preciso para entender como o Bitcoin muda ao longo do tempo sem uma autoridade central para decidir.

## O que você precisa saber primeiro

[Fundamentos da Cadeia de Blocos](../blockchain/README.md), especificamente [Escolha do fork](../blockchain/fork-choice.md) e [Regras de Consenso](../blockchain/consensus-rules.md)Esta seção baseia-se diretamente na distinção entre regras de consenso e regras políticas aí estabelecidas.

## Capítulos

### O vocabulário

1. [Forks de cadeia temporária](./temporary-forks.md): a rotina, do tipo auto-resolver, distinguido de tudo mais nesta seção
2. [Soft forks](./soft-forks.md): aperto de regra, com SegWit como o exemplo trabalhado
3. [Hard fork](./hard-forks.md): alterações de regras que exigem uma atualização universal e o risco real de uma divisão permanente
4. [Compatibilidade para trás](./backward-compatibility.md): o que o termo significa precisamente ao nível das regras de consenso

### Processo

5. [Atualizações de Protocolos](./upgrades.md): o caminho geral da ideia para a mudança implantada
6. [BIP](./bips.md): o processo formal de proposta, modelado nos PEPs do Python
7. [Governança do Bitcoin](./governance.md): quem tem influência prática, e o que cada grupo realmente controla
8. [Sinalização Miner](./miner-signaling.md): BIP 9, o seu limite de 95%, e o que acontece abaixo dele
9. [Soft forks ativados pelo usuário](./uasf.md): alavancagem dos operadores de nó, demonstrada concretamente pelo BIP 148

### Estudos de caso

Apresentado utilizando os argumentos contemporâneos de cada lado, sem adotar a caracterização de ambos os lados.

10. [Bitcoin Cash](./bitcoin-cash.md): o hard fork agosto 2017
11. [Bitcoin SV](./bitcoin-sv.md): um fork de Bitcoin Cash, não de Bitcoin, ea "guerra hash" que se seguiu
12. [SegWit2x](./segwit2x.md): um acordo da indústria que não poderia substituir o consenso da própria rede
13. [Debate sobre o Tamanho do Bloco](./block-size-war.md): a disputa subjacente, genuinamente substantiva por trás dos três
